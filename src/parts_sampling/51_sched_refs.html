Part 4
The big pieces

The five functions that do the work: the three that build the schedule, the one that turns photographs into conditioned tokens, and the three loops that call the network — including the two ways of handling references and the doubled batch of true classifier-free guidance.

§ 12The schedule, in code

Twenty-three lines that produce every number in §2. Three functions, eight fitted constants, two hard-coded thresholds — and one identity that makes the whole thing easy to reason about.

12.1 · generalized_time_snr_shift

∑ The two ends are safe by construction

The expression divides by t, and the schedule always contains t = 1 and t = 0. Neither breaks it. At t = 1 the term (1/t − 1) is exactly 0, so the result is eμ/(eμ+0) = 1. At t = 0 the same term is +inf in IEEE floating point, and eμ/(eμ+inf) = 0 — no exception, no NaN, just the right answer. The endpoints are fixed points of the map for every μ, which is what lets the ladder start at pure noise and end at a finished image no matter how hard it is bent.

12.2 · get_schedule

That the result is a Python list rather than a tensor matters more than it looks. The loop of §14 pairs consecutive entries with zip(timesteps[:-1], timesteps[1:]) and multiplies the difference into a tensor — so the stride is computed in Python floats and only the product is rounded to bfloat16. The time the model is told is rounded, as §3.2 showed; the distance the image moves is not.

12.3 · compute_empirical_mu

◆ The interpolation hits both anchors exactly

With a = (m₂₀₀ − m₁₀)/190 and b = m₂₀₀ − 200a:

at N = 200: a·200 + b = 200a + m₂₀₀ − 200a = m₂₀₀ ✓
at N = 10: a·10 + b = 10a + m₂₀₀ − 200a = m₂₀₀ − 190a = m₂₀₀ − (m₂₀₀ − m₁₀) = m₁₀ ✓

So the names of the two constants are not decorative: they are the values this function returns at ten steps and at two hundred, and every other step count is a straight line between them — extrapolating below 10, which is what all four klein configurations do.

Extrapolation is worth a moment, because four steps is a long way from ten. The slope at 4 096 tokens is a = −0.005822 per step, so going from 10 steps to 4 adds 6 × 0.005822 = 0.035 to μ — a small correction, and one that keeps the ladder in the family the fits describe. Nothing in the file clamps the step count; a one-step run would be given μ = 2.3086 at 4 096 tokens, and the "schedule" would be [1.0, 0.0] — one call at pure noise and one stride covering the whole path, which §3 showed is exact only if the velocity field is.

⚠ The knee at 4 300 is a discontinuity, not a crossover

The two branches agree only at 200 steps, because above the knee the function returns m_200 — the value the lower branch would have produced at exactly 200 steps. At any other step count there is a jump, and §2.3 measured it: for a 4-step run, μ falls from 2.3021 at 4 225 tokens to 1.1940 at 4 356. The threshold is written as a bare integer comparison with no comment, and 4 300 tokens is a square of side 65.57 — not a round number in pixels, in tokens, or in megapixels. Whatever it was fitted to, it was fitted in token space. inference

§ 13encode_image_refs

The only function in the file that calls another model. Thirty-nine lines that take a list of PIL images and return two tensors — the reference tokens and their addresses — ready to be concatenated to the canvas at every step, or cached once.

✦ Why the batch axis is 1 and not B

The function encodes the photos once and returns them with a leading axis of size 1. In denoise those tokens are then concatenated to a canvas of batch size B along the sequence axis — which only works if B is 1, or if every sample in the batch is meant to see the same references. The command-line script generates one image at a time, so the question never arises; a batched caller with per-sample references would have to run this function once per sample. inference

▸ Where the 128 comes from

Each reference token is 128 numbers because that is what the autoencoder emits per patch: 32 latent channels with each 2×2 block of cells folded into the channel dimension, 32 × 2 × 2 = 128. It is the same 128 the canvas noise is drawn with, and the same 128 that img_in in model.py projects up to the hidden size — which is why references and canvas can sit in one sequence at all.
