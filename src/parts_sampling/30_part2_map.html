Code overview

The whole file on one screen: nine lines of imports, twenty-one functions in four families, and the map of who calls whom — including the two files outside this one that use it, and the one function that nothing uses at all.

§ 8The file at a glance

442 lines, twenty-one top-level functions, no classes. Read in file order the file looks scattered — an image helper appears at the very bottom, an unused function sits between two loops — so this chapter reorders it into the four families of §1 and then puts it back together again.

8.3 · Four families, and who calls them

✦ Why the file order is not the reading order

Two functions sit away from their family. concatenate_images — 30 lines of PIL pasting, the longest non-loop function in the file — is the very last thing in it, and is not used by sampling at all: the text encoder imports it to lay reference photos side by side before describing them to a language model. And vanilla_guidance is wedged between denoise_cached and denoise_cfg, which reads like it belongs to the second one; it does not, and nothing calls it (§11). Both are reminders that this file grew as a toolbox for the whole repository, not as a single algorithm written top to bottom.

The schedule — the thing that most changes what the picture looks like — is 23 lines. The image preparation, which exists to stop bad input from reaching the network, is six times that. That ratio is the character of this file: it is mostly getting things into shape, and the algorithm at the centre of it is four lines long.
