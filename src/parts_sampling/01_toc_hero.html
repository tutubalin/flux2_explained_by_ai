FLUX.2, sampling.py,
every single line.

model.py is one function call: give it tokens, a time and a prompt, get back a direction. This is the 442-line file that lives around that call — it decides how many times to make it, at which times, what to put next to the noise, and what to do with the answers. Nothing here has a single trainable parameter, and yet every choice in this file changes the picture you get.

It is the companion to FLUX.2 model.py, every line explained, and it is written to be read on its own: Part 1 explains the sampler from zero with pictures and no source code at all, and Parts 3 and 4 then walk through all 442 lines.

◆ How this article was checked

Every claim marked VERIFIED came from running the code. The file reproduced here is byte-identical to the upstream source — its git blob hash is 1b581083d2bd603ef3eb79605ee5321fc36bff01, matching black-forest-labs/flux2@main. Every schedule printed in this article was produced by calling get_schedule and compute_empirical_mu themselves; the pixel budgets, crops and token counts were produced by calling cap_pixels and center_crop_to_multiple_of_x; and the claim that the timestep shift is a translation in logit space was checked to 10−12 at sixteen points. The script is src/ref/verify_sampling.py in this repository, and it runs on every build.

Six more checks run on every build, because this page quotes real source line numbers all the way through, and any one of them stops the build. qa_trace.py verifies that every line-by-line annotation points at lines containing the identifiers it talks about; qa_coverage.py verifies that all 348 non-blank lines of the file are shown somewhere; qa_linerefs.py checks every place where the prose cites a line number against what really sits on that line; qa_xrefs.py resolves every "see §12.3" and "FIG 7"; qa_order.py fails if any chapter tells the reader they have already met something a later chapter explains; and verify_sampling.py re-derives every number quoted here from the source and then looks for it in the finished page. The same six gates build the model.py article — the two pages share one stylesheet, one builder and one checker suite.

One convention to know: numbers and structure are checked against the code, but the file carries almost no comments, so a statement about why the authors chose something is marked inference. The page carries of these badges, this one included — everything else in it is in the source or in the published papers listed in §20.
