§ 6Two ways to be guided

The word "guidance" appears in every signature in this file, and it means two completely different things depending on which checkpoint you loaded. One is a number the network was trained to obey; the other is a subtraction performed outside the network. Confusing them is the easiest way to misread the three loops.

6.1 · Route A — guidance as an input

A guidance-distilled model has learned to take a strength dial as part of its input. The loop builds a tensor filled with that one float, hands it over with every call, and the network embeds it exactly the way it embeds the timestep: a 256-number sinusoidal code, a two-layer MLP, and a vector added to the timestep vector that steers every block. One batch, one call per step, no arithmetic afterwards.

pred = model(x, t, ctx, guidance=w) and that is the whole of it — nothing is combined or extrapolated

6.2 · Route B — guidance as an extrapolation

An ordinary model has no dial. To make it obey a prompt more strongly you run it twice per step — once on the real prompt and once on an empty one — and push the difference further than the model itself would:

pred = pred_uncond + w·(pred_cond − pred_uncond)

At w = 1 this returns the conditional prediction untouched. At w = 0 it returns the unconditional one — what the model would paint with no prompt at all. FLUX.2's non-distilled models ship with w = 4, which means going four times as far from "no prompt" as the network suggested, in the direction of "your prompt".

6.3 · Which checkpoint takes which route

The choice is not made in this file. sampling.py offers all three loops; the script picks one from a single flag in the checkpoint's metadata, guidance_distilled:

⚠ The klein models are handed a guidance number they cannot read

All three loops build a guidance tensor and pass it on — denoise fills it with the configured value, denoise_cfg fills it with None. Inside model.py the embedding is guarded: if self.use_guidance_embed: vec = vec + self.guidance_in(…), and the klein parameter sets have use_guidance_embed = False. So for klein-4B, klein-9B and klein-9B-kv the value 1.0 travels into the network and is dropped on the floor: there is no guidance_in module to receive it. The loops are written as if every model had a dial, and only flux.2-dev does.

The mirror image is also true: denoise_cfg passes guidance=None, which is safe for the base klein models precisely because they never look. Hand the same function a distilled model and that None would be passed straight to the timestep embedding. The three loops and the checkpoint families line up one-to-one, and the pairing is enforced by the script, not by this file. inference

✦ Why the caller doubles the text and the loop doubles the image

In denoise_cfg the image is duplicated inside the function (img = torch.cat([img, img], dim=0)) but the prompt is not — it arrives already doubled, and the signature says so in a comment: txt # Already cat([txt_empty, txt_prompt]). The two halves of the text batch are different (empty, then real), so they have to be built by whoever has both strings; the two halves of the image are identical, so the loop can make them itself. The division of labour follows the data, not a convention.

§ 7Caching at the loop level

The third loop exists for one arithmetic fact: with reference images, most of what the network looks at does not change between steps. Recomputing it fifty times is the single largest waste in a FLUX.2 edit — and removing it changes the mathematics, which is why it needs its own checkpoint.

7.1 · What is actually constant

Take one reference photograph and a 512×512 canvas. The image-side sequence the network attends over is 15 876 reference tokens plus 1 024 canvas tokens: 94 % of it is the photograph. Now ask what changes from step to step:

QuantityBetween two consecutive steps
Reference token contentIdentical. The encoded photo never changes during a generation.
Reference token addressesIdentical. ref_ids is built once, before the loop.
Reference tokens' timestep in the cached pathIdentical — and not merely in practice: forward_kv_extract gives the references a fixed timestep of ref_fixed_timestep = 0.0, and denoise_cached never overrides it. To the network, a reference is always a finished image, never a noisy one.
Reference tokens' timestep in the plain pathChanges. In denoise the references are simply concatenated to the canvas and the whole sequence is processed at the current t, so their modulation — and therefore their keys and values — is different at every step.
Canvas tokensChange every step. That is the point of the loop.

So in the plain path nothing can be cached: the references really are recomputed, and they really do produce different keys and values each time. Caching is not an optimisation of denoise — it is a different model of the world in which the references are frozen at t = 0 and their contribution is computed once.

7.2 · What the cache costs

Keys and values are not free. Every block stores two tensors of hidden_size numbers per cached token, in bfloat16 — so four bytes per token per block for K and V together:

bytes per cached token = 2 × hidden × 2 bytes × blocks = 4 × hidden × (double + single)

Which is why the cached variant exists only for klein-9B: it is the configuration where the memory fits and the saving is largest. Four references at 512² mean the plain loop pushes 17 408 image-side tokens per step and the cached loop pushes 1 024. Counting the 512 text tokens that both paths process, the whole sequence goes from 17 920 to 1 536 — a factor of 11.7 in tokens — and the published measurement is 2.66× in wall-clock time, because the work that does not scale with the reference count still has to happen: the canvas's own attention, every MLP, and all of the modulation.

✦ Caching is a modelling choice wearing an optimisation's clothes inference

Freezing the references at t = 0 and refusing to let them see the canvas change is not the same computation as denoise performs — the repository says so by shipping a separate checkpoint, flux.2-klein-9b-kv, for the cached path. The two loops are not interchangeable and the numbers they produce are not equal.
