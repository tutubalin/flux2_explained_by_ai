§ 9Time and guidance — how one float steers 32 billion weights

§6 built attention out of nothing and §8 built positions out of nothing, because every block in this file is wired around both. This section does the same for the third thing every block needs and the file never stops to define: how the network is told what to draw, and how noisy its input is. Nothing here is in model.py as a single named object — it is a mechanism spread over one function, one small class and one three-line class (§16.1, §16.3, §16.9) and consumed in all 56 blocks. Understand it once here and those three classes become trivial.

9.1 · One set of weights, fifty different jobs

Recall the loop from §1: generating one image means calling the same network many times — 50 times for FLUX.2-dev, 4 for the klein models — with a timestep t that walks down from 1 to 0. Those calls cannot want the same thing.

the call atwhat the input looks likewhat a useful output looks like
t = 0.98almost pure Gaussian noise — no objects, no layouta coarse global arrangement: where the subject is, how big, what the lighting does. Fine detail is meaningless here; there is nothing yet to refine.
t = 0.50a blurry but recognisable imageshape and texture decisions: edges placed, materials chosen
t = 0.05nearly the finished imagea small correction — sharpen here, fix a colour there. A coarse global decision now would destroy the picture.

So one fixed function has to behave like a different function at every step. There are only three ways to arrange that:

  1. Build one network per step. 50 copies of a 32-billion-parameter model. Absurd, and it could not generalise to a step count chosen at run time.
  2. Hand t to the network as another input token and let attention find it. Possible — but a single token among 16 896 is a weak, indirect signal, and every block would have to spend attention capacity re-discovering it.
  3. Keep one set of weights and let t re-tune them on the fly. No weight is ever changed; instead each layer's normalisation is shifted, scaled and gated by numbers derived from t. One network, fifty behaviours, almost no extra parameters.

FLUX.2 does the third. The mechanism is called adaptive layer normalisation (adaLN), and the rest of this section builds it from the ground up.

9.2 · Three ways to tell a network something

Before the mechanics, one distinction explains the whole design. A diffusion transformer has to be told several different things, and FLUX.2 tells them through different channels:

💡 The rule behind the split

Content goes into the sequence; settings go into the modulation. A prompt is content: different image regions need to look at different words, and only attention can route one token to another (§6). A timestep is a setting: it has to apply to every token in every layer at once, uniformly. Broadcasting one scalar through attention would be slow and lossy; handing it to each layer's normalisation reaches all 16 896 tokens in one multiplication. The guidance value is a setting for the same reason — it says "push harder towards the prompt", not "look at this".

9.3 · The other setting: what "guidance" actually is

The loop above passes the model four things — noisy latents, their position ids, the timestep, the text — and for some checkpoints a fifth: guidance. It is one number, and the file never explains it, so here it is. It matters twice: it is the second "setting" that §9 routes into the network, and it is a config field in §15 (use_guidance_embed).

The problem. A model trained to follow a prompt follows it politely. It produces something consistent with the words but hedged — washed out, under-committed, averaging over everything the prompt could have meant. Classifier-free guidance (Ho & Salimans, 2022 — §26) is the classic fix: run the network twice per step, once with the prompt and once with an empty one, and extrapolate past the conditional prediction.

Σ Classifier-free guidance, one step

v = v_uncond + w · (v_cond − v_uncond)

w = 1 → the plain conditional prediction · w > 1 → step further along "what the prompt changes" · w = 0 → ignore the prompt

The bracket is exactly what the prompt changes, so multiplying it by w > 1 amplifies only that. It works — and it doubles the cost: 100 network evaluations for a 50-step image.

What FLUX.2 does instead. use_guidance_embed says whether the model takes w as an input. Where it does, the value is fingerprinted and embedded exactly like the timestep and added to the same condition vector (§9.4), so a single pass approximates what the two-pass extrapolation would have produced — the model was trained to reproduce it, which is what "guidance distillation" means. The dev configuration sets use_guidance_embed=True and util.py drives it with guidance=4.0 over 50 steps. Both klein configurations set it to False: those networks have no guidance input at all, and util.py accordingly runs them with guidance=1.0 — no amplification — in 4 steps.

sampling.py still carries the two-pass version as its own entry point (denoise_cfg): it duplicates the batch, passes guidance=None to the model, and combines the two predictions outside the network. Same idea, no distilled input, twice the compute.

⚠ Do not confuse the two

A distilled guidance value — this file's guidance_in — is one scalar fed into one forward pass. True classifier-free guidance is two forward passes combined afterwards. Nothing in model.py ever does the second: the file only sees the scalar.

9.4 · From one float to 56 blocks' worth of dials

Now the pipeline that produces those dials. It has four stages, and each one exists because the previous one is not enough.

Stage 1 — the fingerprint. §7 built this one: t is multiplied by 1000 and read against 128 geometrically spaced frequencies, each reading taken twice — a cosine and a sine — which gives 256 numbers between −1 and 1. No parameters, nothing learned, smooth in t, and no two times in [0, 1] share a fingerprint. The fastest reading completes 159 cycles over a whole run and the slowest 1.7 % of one; that spread of scales is the entire trick, and it is what turns one float into something a 6144-wide matrix can actually work with.

Stage 2 — a fixed code becomes a learned meaning. The fingerprint is a deterministic function of t: no parameters, nothing learned. What it means to be at t = 0.62 is something the model has to discover, so the fingerprint goes through the smallest possible learned transform — two linear layers with a nonlinearity between them, 256 → 6144 → 6144 (§16.3). The nonlinearity is SiLU, silu(x) = x · σ(x) — a smooth, self-gated ramp that is near zero for very negative inputs and near x for positive ones. §16.2 turns that same function into a gate for the MLPs; here it is just the kink that lets two linear layers express more than one. Its output is the condition vector, vec, and it is the only form in which the timestep ever reaches the blocks.

Stage 3 — the guidance value takes the same road and is added. If the configuration has use_guidance_embed (§15, true for dev only — and §9.3 explains what the value means), the guidance scalar is fingerprinted and MLP'd through its own copy of the same class, and the two vectors are summed (L200–203):

Σ Two settings, one channel

vec = time_in(fingerprint(t)) + guidance_in(fingerprint(g))

(B, 6144) + (B, 6144) → (B, 6144)

Adding, rather than concatenating, means the two settings share every downstream matrix: there is one condition channel and the network learns to disentangle them. It also means guidance cannot be routed somewhere the timestep does not go — the two dials are fused from this point on.

Stage 4 — three matrices turn one vector into everybody's dials. vec is fed to three Modulation modules (§16.9). Each one applies SiLU and then a single bias-free linear layer, and splits the result into vectors of 6144:

module (built at L98–108)its matrixvectorswho consumes them
double_stream_modulation_img6144 → 36 8646the image stream of all 8 double blocks: (shift, scale, gate) for its attention, then (shift, scale, gate) for its MLP
double_stream_modulation_txt6144 → 36 8646the text stream of the same 8 blocks, same two triples
single_stream_modulation6144 → 18 4323all 48 single blocks — one triple, because after the merge there is one stream and one fused sub-layer

That is the naming trap in __init__: double=True does not mean "one triple per stream in a two-stream block". Each of the two double=True modules serves one stream and emits two triples — one for attention, one for the MLP. Six vectors, one stream.

◇ If you have never seen conditioning done this way

The one-sentence version: the timestep does not enter the network as data, it enters as a setting. A tiny side-network reads t and produces a handful of numbers per block; those numbers are multiplied and added into the activations at every normalisation point, so the same weights compute a different function at every step. Compare it with the two alternatives you may know from other models: a U-Net adds a time embedding to its feature maps (FiLM-style, the same family of idea), and a cross-attention model inserts the condition as extra keys and values (which is what FLUX.2 does for the prompt, not for the timestep).

That is the whole of this chapter's job: two settings in, one vector out. What fifteen dial vectors then do to 56 blocks — why they attach at the layer norms, what the third dial is for, and what sharing them costs — is §11, which picks up exactly here.
