§ 11Modulation — how a vector steers 56 blocks

§9 ended with a vector: vec, 6 144 numbers that encode "how noisy is this input, and how hard should I push towards the prompt". This chapter is about what a vector like that can actually do to a network — the mechanism, the three dials, where they attach, and what the whole arrangement costs. There is no code here; the thirteen lines that implement it are §15.9.

11.1 · The idea, and the word for it

A neural network's behaviour is normally fixed once training stops: the weights are the behaviour. To make one network behave differently at different moments you have three options — change the weights (impossible at run time), change the input (limited: you can only tell it things through the data it already reads), or change the settings the computation runs under. The third is modulation, and the family of techniques goes by the name FiLM — feature-wise linear modulation — which means: multiply some activations by a number and add another, where both numbers come from somewhere else.

The name to know is adaptive layer normalisation, adaLN: FiLM applied at the normalisation inside each transformer sub-layer, with the condition vector as the source of the numbers. DiT (Peebles & Xie, 2022 — §25) made it the standard for diffusion transformers, and FLUX.2 uses it in every one of its 56 blocks plus the exit door.

11.2 · LayerNorm from zero — and why it is the place to inject

A layer norm acts on one token vector at a time — D numbers, independently of every other token, so it can never leak information between positions. It does two things:

Σ LayerNorm, in full

μ = mean(x) σ² = mean((x − μ)²) x̂ = (x − μ) / √(σ² + ε)

y = γ ⊙ x̂ + β

x is (L, D) · μ, σ², x̂, y are (L, D) · γ and β are (D,) — one number per channel, shared by all tokens · ⊙ is element-wise multiplication

The first line is normalisation: subtract the token's own mean, divide by its own standard deviation. After that, every token vector has mean 0 and unit variance, whatever it was before. Why bother? Because 56 blocks of matrix multiplication would otherwise let magnitudes drift — one block's output becomes the next block's input, and a weight matrix that happens to amplify by 1.1× compounds into something unmanageable over 56 layers. Normalising resets the scale at every step, so each block always sees an input in the range its weights were trained for.

The second line is the part that matters here. After x̂, the vector's scale and offset are fixed — the only freedom left in the whole operation is γ (a per-channel gain) and β (a per-channel offset). Those two are the knobs.

  • Let γ and β be learned constants and you have ordinary LayerNorm: the knobs are set once, at training time, and never move again.
  • Let γ and β be computed from something else — the timestep — and you have a layer whose behaviour changes from step to step while every weight in it stays frozen. Two knobs, turned 50 times, giving 50 different layers out of one.

That is the entire trick, and the file is built around it. PyTorch's nn.LayerNorm(D, elementwise_affine=False) deletes γ and β, leaving a module that only normalises. FLUX.2 uses exactly that setting in all 81 of its layer norms — the census in §13.1 — and supplies γ and β from the timestep instead. In the code they are spelled

Σ How the knobs are written in this file

x_mod = (1 + scale) ⊙ norm(x) + shift

L470 in the single block · L580 and L588 in the double block, before attention · L628 and L633, before the two MLPs

scale is playing γ's role and shift is playing β's. The 1 + is not decoration: with scale = 0 you get exactly the normalised signal, so "nothing special is happening" is the default state and the network only has to learn a deviation from it. It is the same idea as a residual connection, applied to the modulation itself — and it is why the modulation can be shared by 56 blocks without every block being forced into the same extreme behaviour.

11.3 · Shift, scale, gate: three dials per sub-layer

Shift and scale re-tune what a block sees. DiT (Peebles & Xie, 2022 — see §25) added a third dial, and FLUX.2 keeps it: a gate that multiplies the sub-layer's output before it is added back into the residual stream.

◇ The residual stream, in one paragraph

Every token owns a vector of 6144 numbers that is carried through the whole network, and each block adds to it instead of replacing it: x ← x + block(x). That running vector is the "residual stream" — the token's current understanding of itself, which starts as a projected patch (§4) and ends as a velocity (§1). Two things follow, and both matter below. A block cannot destroy what earlier blocks decided, only amend it — which is what makes 56 layers trainable at all. And a block that contributes nothing is a perfectly valid state: set its output to zero and the stream passes through unchanged. That is why a gate is worth having — next — and why the merged stream in §19.2 can be handed to 48 further blocks without any rewiring.

Σ One adaLN sub-layer

x ← x + gate ⊙ sublayer( (1 + scale) ⊙ norm(x) + shift )

shift, scale, gate are all (B, 1, D) — one value per channel, broadcast over all L tokens

Think of the gate as a volume knob on the block's contribution. gate = 0 and the block is a no-op — the stream passes through untouched, however excited its internals got. gate = 1 and the block's full output lands in the stream. In between, the block contributes partially. Shift and scale cannot do that: they change the input, so the block always runs, and its output always arrives. The gate is what lets the same 56 blocks do coarse global work at t = 0.98 and delicate local work at t = 0.05 — different layers can be turned up or down per step.

DiT initialises its gate to zero — "adaLN-Zero" — so that a freshly initialised block is the identity and a deep network starts out as a no-op that training gradually switches on. model.py contains no initialisation code at all (every matrix is a plain nn.Linear(..., bias=False) and the checkpoints arrive trained), so whether FLUX.2's gates started at zero cannot be read off this file.

Sharing the modulation is not this file's invention, and the family tree makes the numbers above make sense. DiT (2022) gave every block its own modulation MLP — row two of that table — and FLUX.1 still does. PixArt-α (2023) noticed the price and introduced adaLN-single: one shared global vector, refined per block by adding a small learnable bias. FLUX.2 drops the refinement as well. The three modules of L98–108 are the whole mechanism; a block's private reaction to t has to come out of its own weights.

That is the single largest saving in the file, and §13.1 counts it as ~8.5 billion parameters — about 17 GB that a 32-billion-parameter model does not have to carry next to its activations. Which side of that trade the authors were optimising is not recorded anywhere in the source. inference What is in the source is the price paid: with shared modulation, every block receives the same three (or six) dials, so a block cannot have a private reaction to the timestep. It can only react differently because its weights differ. Fifty-six blocks get fifty-six different responses to t out of one broadcast triple each.

The second consequence is the one that generates real code. A broadcast dial cannot distinguish one token from another — it is (B, 1, 6144), the same for every position. But reference tokens have to be conditioned at t = 0 while the canvas sits at t = 0.62 (§21.1 explains why). One shared triple cannot say that. So forward_kv_extract runs the modulation twice: once with the real timestep, and once with a timestep pinned to 0.0 for the references (L198, L206–211).

Two runs produce two sets of dials, but every block receives one. So the two sets are spliced into a per-token tensor whose first rows come from the reference run and whose remaining rows come from the real one — and that splice is the entire reason _blend_mod_triple, _blend_double_mods and _blend_single_mods (§20) exist. Shared modulation is cheap; this is the bill.
